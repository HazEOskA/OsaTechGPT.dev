Agent Proof Runtime: weryfikowalne dowody autonomicznej pracy AI

APR zamienia wynik agenta w sprawdzalny ślad dowodowy zamiast demonstracji „uwierz mi”. Granice misji, deterministyczne checki, integralność evidence i niezależny verifier tworzą jedną ścieżkę proof.

TWIERDZENIE ≠ DOWÓD. Brak dowodu = UNKNOWN.
Definicja

Czym jest Agent Proof Runtime

APR jest runtime’em dowodowym dla autonomicznej pracy AI. Jego rolą nie jest sprawienie, żeby agent brzmiał przekonująco, tylko związanie konkretnego wykonania z konkretną misją, obserwacjami i wynikiem weryfikacji.

MISJA → WYKONANIE → CHECK → EVIDENCE → PROOF BUNDLE → VERIFY

Agent nie przyznaje sam sobie statusu sukcesu. Wynik musi przejść przez niezależną ścieżkę weryfikacji.

Statusy

Brak dowodu nie staje się zielonym wynikiem

APR rozróżnia m.in. LOCAL_VERIFIED, FAILED i UNANCHORED. Dzięki temu lokalny check integralności nie jest przedstawiany jako zewnętrzne zakotwiczenie czy hardware-backed trust.

Najważniejsza właściwość: nie „zaufaj runtime’owi, bo mówi verified”, tylko „sprawdź evidence i uruchom verifier ponownie”.

Komponenty

Co znajduje się w APR

  • Mission Control — uruchamianie i inspekcja misji.
  • Proof Bundle — wersjonowany pakiet evidence.
  • Niezależny verifier — ponowna kontrola integralności i wymagań.
  • Tamper Lab — demonstracja wykrywania zmodyfikowanych dowodów.
  • Mission Studio — pipeline wielu agentów za jedną granicą proof.

Rola

Proof uzupełnia governance

Kontrola przed wykonaniem odpowiada na pytanie „co agent może zrobić?”. APR odpowiada na inne: „jakie dowody pokazują, co rzeczywiście się wydarzyło?”. Obie warstwy są potrzebne.
