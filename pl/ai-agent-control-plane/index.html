Architektura · Control Plane

Control plane agentów AI: source-to-runtime evidence dla operatora

Control plane nie powinien tworzyć drugiej fikcyjnej rzeczywistości. Ma połączyć źródło kodu, evidence z chmury i działania operatora w jeden traceable surface.

TWIERDZENIE ≠ DOWÓD. Brak dowodu = UNKNOWN.
Definicja

Control plane nie jest source of truth

OSA Cloud Workspace traktuje GitHub jako source of truth dla kodu, a cloud runtime jako źródło prawdy dla infrastruktury i wykonania. Workspace jest warstwą operatora nad tymi źródłami.

GITHUB — source / branch / SHA → CLOUD BUILD → ARTIFACT / IMAGE DIGEST → READY REVISION → LIVE URL → OPERATOR
Deployment proof

„Build success” nie kończy dowodu wdrożenia

Canonical chain to SOURCE SHA → BUILD ID → IMAGE DIGEST → READY REVISION → LIVE URL. Każdy etap odpowiada na inne pytanie o to, jaki kod rzeczywiście działa.

Operator

Jedna powierzchnia, wiele systemów

Workspace obejmuje agents, automations, project portfolio, dev tools, test lab, deployment, infra i costs. Kluczowe jest powiązanie repo, branch, SHA, deployment evidence i live targetu.

Governance

Control plane i runtime governance rozwiązują inne problemy

UI ułatwia operatorowi widzieć i uruchamiać pracę. Runtime governance decyduje czy agent ma authority, jakie capability istnieją i jaki proof jest wymagany. UI nie może być jedyną granicą bezpieczeństwa.
