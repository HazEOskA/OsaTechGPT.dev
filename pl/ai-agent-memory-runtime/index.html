Runtime pamięci agentów AI: trwały state bez ukrytej pamięci

Warstwa pamięci powinna przeżywać sesje bez zamiany w nieprzejrzystą bazę, która po cichu zmienia zachowanie agenta. Persistent state potrzebuje jawnej struktury, limitów i provenance.

Definicja

Pamięć to runtime state, nie tylko retrieval

Vector search pomaga znaleźć tekst, ale trwała pamięć agentowa ma szersze zadanie: zachować strukturę stanu, relacje dokumentów, activation history i provenance zapisów między restartami i sesjami.

Compiler path

State transitions zaczynają się od programu

.nsa → lexer → parser → AST → analiza semantyczna → type checks → IR 0.1 → runtime → activation → SQLite → hash-chain ledger

NeurOSA obsługuje neurony, synapsy pobudzające i hamujące, ograniczoną propagację impulsów, activation traces, persistent state i recovery po restarcie.

Dokumenty

Dokumenty pozostają first-class state

Natywny workspace obsługuje Markdown, frontmatter, tagi, headings, wikilinki, backlinki, piny, ulubione, kosz, immutable revisions i SQLite FTS5. Po imporcie dane nie wymagają Obsidiana.

Connect & Ingest

Jedno Brain API dla sesji i importów

Connect utrzymuje trwałe sesje i atomowe zapisy do dokumentów i ledgeru. Ingest przyjmuje materiały z Drive, PDF, DOCX, tekst i eksporty rozmów. HTTP i MCP korzystają z tego samego Brain API.

Ledger

Provenance pamięci można sprawdzić mechanicznie

Append-only ledger używa SHA-256 i jest przechowywany ze stanem runtime’u w SQLite. verifyLedger() wykrywa zmianę payloadu, usunięcie lub przestawienie eventu oraz błędne hashe.
